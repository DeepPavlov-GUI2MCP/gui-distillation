# Skill Formalization

**Проект:** Дистилляция GUI-навыков из MLLM  
**Фаза:** 0.2 Skill Formalization  
**Дата:** 2026-02-17  
**Исполнитель:** RT  
**Целевое приложение:** GNOME Calculator  

---

## 1. Введение

В рамках методологии выделяются **4 базовых навыка**, которые в совокупности покрывают весь цикл взаимодействия с GUI-приложением:

1. **SimplifierTask (Skill 0)** — декомпозиция высокоуровневого запроса на атомарные задачи  
2. **GroundingTool (Skill A)** — локализация элемента по описанию  
3. **ActionModel (Skill B)** — выбор действия и его параметров  
4. **StateModel (Skill C)** — интерпретация изменения состояния  

Данный документ формализует каждый навык применительно к GNOME Calculator.

## 2. Skill 0: SimplifierTask (Декомпозиция запроса)

### 2.1. Назначение
Преобразовать высокоуровневую инструкцию пользователя в последовательность атомарных задач, которые можно выполнить по одной.

### 2.2. Вход/Выход

**Вход:** "посчитай 2 + 2 * 3"
**Выход:** [enter_number(2), operation(+), enter_number(2), operation(*), enter_number(3), compute()]

### 2.3. Словарь атомарных задач (Atomic Tasks)

| **enter_number** | Ввод числа        | Ввести многозначное число   | `value: число`                   | `enter_number(42)` |  
| **enter_digit**  | Ввод цифры        | Нажать одну цифру           | `digit: 0-9`                     | `enter_digit(5)`   |  
| **operation**    | Бинарная операция | +, -, ×, ÷                  | `op: "+"/"-"/"*"/"/"`            | `operation("+")`   |  
| **unary**        | Унарная операция  | √, %, 1/x                   | `op: "sqrt"/"percent"/"inverse"` | `unary("sqrt")`    |  
| **compute**      | Вычислить         | Нажать =                    | —                                | `compute()`        |  
| **clear**        | Полная очистка    | Сброс калькулятора (C)      | —                                | `clear()`          |  
| **clear_entry**  | Очистка ввода     | Очистить текущее число (CE) | —                                | `clear_entry()`    |  
| **toggle_sign**  | Смена знака       | +/-                         | —                                | `toggle_sign()`    |  
| **add_decimal**  | Десятичная точка  | Добавить .                  | —                                | `add_decimal()`    |  

### 2.4. Примеры декомпозиции

| "5 + 3"               | `[enter_digit(5), operation("+"), enter_digit(3), compute()]`     |  
| "корень из 16"        | `[enter_number(16), unary("sqrt")]`                               |  
| "очисти и введи 3.14" | `[clear(), enter_number(3.14)]`                                   |  
| "посчитай 2.5 * 4"    | `[enter_number(2.5), operation("*"), enter_number(4), compute()]` |

## 3. Skill A: GroundingTool (Локализация элемента)

### 3.1. Назначение
По скриншоту и текстовому описанию найти bounding box элемента, о котором идет речь.

### 3.2. Вход/Выход

**Вход:** screenshot, instruction = "кнопка 5"  
**Выход:** bbox = [0.35, 0.50, 0.40, 0.55] # [x_min, y_min, x_max, y_max] (нормализованные)  
confidence = 0.98  
element_type = "digit_button"  

### 3.3. Типы элементов (Element Types)

| `digit_button`       | Кнопка с цифрой | "пять", "кнопка 7", "цифра ноль" |  
| `operation_button`   | Кнопка операции | "плюс", "сложение", "умножить"   |  
| `equals_button`      | Кнопка равно    | "равно", "посчитать", "="        |  
| `clear_button`       | Кнопка C        | "очистить", "сброс", "C"         |  
| `clear_entry_button` | Кнопка CE       | "CE", "очистить ввод"            |  
| `sign_button`        | Кнопка +/-      | "сменить знак", "+/-"            |  
| `decimal_button`     | Кнопка точки    | "точка", "десятичная"            |  
| `display`            | Дисплей         | "экран", "дисплей", "результат"  |  

### 3.4. Примеры входных инструкций

**По содержимому:**  
- "пять", "цифра 5", "кнопка с цифрой 5"  
- "плюс", "сложение", "знак плюс"  
- "равно", "посчитай"  

**По положению:**  
- "верхняя правая кнопка"  
- "кнопка слева от плюса"  
- "нижний ряд, третья кнопка"  

**По функции:**  
- "очистить всё"  
- "сменить знак"  
- "десятичная точка"

## 4. Skill B: ActionModel (Выбор действия)

### 4.1. Назначение
Определить, какое действие нужно выполнить с найденным элементом, и с какими параметрами.

### 4.2. Вход/Выход

**Вход:** screenshot, instruction = "нажми 5", bbox от Grounding  
**Выход:** action_type = "click"  
parameters = {"button": "left", "clicks": 1}  
confidence = 0.99  

### 4.3. Словарь действий (Action Types)

| **click**        | Одиночный клик | `button: "left"/"right"/"middle"`, `clicks: 1` | 99% случаев в калькуляторе            |  
| **double_click** | Двойной клик   | `button: "left"`                               | Редко, если нужно выделить            |  
| **right_click**  | Правый клик    | —                                              | Для контекстного меню (если появится) |  
| **hover**        | Наведение      | —                                              | Для подсветки (не используется)       |  

### 4.4. Особенности для калькулятора
- В калькуляторе все действия — **click**  
- Координаты клика — центр bbox или случайная точка внутри  
- Двойные/правые клики не имеют смысла

## 5. Skill C: StateModel (Интерпретация изменения)

### 5.1. Назначение
После выполнения действия оценить, что изменилось, успешно ли оно выполнено, и описать изменение семантически.

### 5.2. Вход/Выход

**Вход:** screenshot_before, action, screenshot_after  
**Выход:** success = true  
change_type = "display_updated"  
display_before = "2"  
display_after = "5"  
description = "На дисплее было 2, после нажатия '5' стало 25"  

### 5.3. Типы изменений (Change Types)

| **display_updated**   | Обновилось содержимое дисплея         | 2 → 25                        |  
| **error_occurred**    | Появилась ошибка                      | "Error" при делении на 0      |  
| **error_cleared**     | Ошибка исчезла                        | Нажали C после ошибки         |  
| **mode_changed**      | Сменился режим                        | Basic → Advanced              |  
| **no_change**         | Ничего не изменилось                  | Нажали C когда уже пусто      |  
| **unexpected_change** | Изменение не соответствует ожидаемому | Нажали 5, а дисплей очистился |  

### 5.4. Типы ошибок (для failure случаев)

| `element_not_found` | Элемент не найден           | Клик по несуществующей кнопке |  
| `no_reaction`       | Приложение не отреагировало | Клик, но ничего не изменилось |  
| `wrong_result`      | Неправильный результат      | 2+2=5                         |  
| `unexpected_error`  | Непредвиденная ошибка       | Появилось неожиданное окно    |

## 6. Форматы данных

### 6.1. Координаты (Bounding Box)

**Формат:** нормализованные координаты [0, 1]

```python
class BBox:
    x_min: float  # от 0 до 1
    y_min: float  # от 0 до 1
    x_max: float  # от 0 до 1
    y_max: float  # от 0 до 1
```

**Обоснование:** Независимость от разрешения экрана.

### 6.2. JSON Schema (пример для Grounding)

```
{
  "input": {
    "screenshot": "base64_encoded_image",
    "instruction": "кнопка 5"
  },
  "output": {
    "bbox": [0.35, 0.50, 0.40, 0.55],
    "confidence": 0.98,
    "element_type": "digit_button"
  }
}
```

## 7. Обоснование декомпозиции на 4 навыка

**Simplifier** - декомпозиция запроса (отделяет понимание задачи от выполнения)  
**Grounding** - поиск элемента (можно переиспользовать для разных действий)  
**Action** - выбор действия (один элемент - разные действия (клик/правый клик))  
**State** - оценка результата (обратная связь для агента, детекция ошибок)  

Преимущества такого разделения:  
- Модульность — каждый навык можно улучшать независимо  
- Переиспользование — Grounding пригодится для любого GUI  
- Тестируемость — каждую модель можно оценить отдельно  
- Масштабируемость — легко добавить новый навык
